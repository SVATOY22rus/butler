# Butler — чек-лист проверки

Инструкция для тестировщика. Проходится сверху вниз, каждый шаг содержит
ожидаемый результат. Если шаг не совпал — зафиксируйте вывод команды целиком
и переходите к разделу [Диагностика](#диагностика).

**Тестировать только на виртуальной машине или тестовом сервере.** Butler
меняет правила фаервола и `/etc/sudoers`, ошибка в настройке может отрезать
SSH-доступ.

---

## 0. Что понадобится

- Тестовая ВМ с Astra Linux 1.8, Debian 12 или Ubuntu 22.04+
- Доступ по SSH и право `sudo`
- **Резервный способ входа на ВМ** (консоль гипервизора или снапшот) — страховка
  от блокировки SSH
- Отдельная машина для сборки архива, с доступом в интернет

Перед началом сделайте снапшот ВМ.

---

## 1. Подготовка сервера

```bash
python3 -V
sudo apt update
sudo apt install -y python3 python3-venv ufw conntrack
```

**Ожидается:** версия Python выведена, пакеты установлены без ошибок.
Запишите версию — на Astra 1.8 это `3.11.x`.

---

## 2. Сборка архива

На сборочной машине. Замените `cp311`/`3.11` на версию из шага 1.

```bash
git clone https://github.com/SVATOY22rus/butler.git
cd butler
./build.sh --python-version 3.11 --abi cp311
```

**Ожидается:**
- строка `[✓] Wheels скачаны: N файлов (ABI cp311).` — в скобках должен стоять именно ваш ABI
- список всех обязательных файлов с зелёными галочками
- строка `[✓] Готово к деплою.`
- архив `../butler-<дата>.tar.gz`

Контрольная проверка ABI:

```bash
tar -tzf ../butler-*.tar.gz | grep -i markupsafe
```

**Ожидается:** в имени файла присутствует `cp311`. Если там другой `cpXXX` —
это дефект сборки, дальше идти нет смысла.

### 2.1 Негативная проверка сборки

```bash
./build.sh --python-version 3.11 --abi cp999
```

**Ожидается:** сборка **падает** с сообщением `Не удалось скачать wheels под
cp999 / manylinux2014_x86_64`. Архив не создаётся.
Если сборка прошла «успешно» — дефект: ошибка проглатывается.

---

## 3. Установка

```bash
scp butler-*.tar.gz user@server:~/
ssh user@server
tar -xzf butler-*.tar.gz
cd butler
```

Настройте конфиг до установки:

```bash
cp butler.env.example butler.env
python3 -c "import secrets; print(secrets.token_hex(32))"   # вставить в BUTLER_SECRET_KEY
nano butler.env
```

Задайте `BUTLER_SECRET_KEY`, `BUTLER_ADMIN_USER`, `BUTLER_ADMIN_PASS`.
Запишите логин и пароль — они понадобятся на шаге 5.

```bash
./install.sh
```

**Ожидается:**
- `[✓] venv создан`
- `[✓] Зависимости установлены.`
- `Database initialized and demo data added.`
- `[✓] Служба запущена и работает.`
- `[✓] Таймер автосбора логов включён (каждые 5 минут).`
- итоговый блок с адресом `http://<ip>:5050`

**Не ожидается:** `ERROR: Could not find a version that satisfies the
requirement MarkupSafe` — это означает несовпадение ABI, вернитесь к шагу 2.

Проверка:

```bash
systemctl is-active butler          # active
systemctl is-active butler-log-import.timer   # active
ss -tlnp | grep 5050                # порт слушается
```

## 4. Права на UFW

```bash
./sudoers.sh
```

**Ожидается:** `[✓] Sudoers настроен для пользователя: <ваш логин>` —
именно ваш логин, **не `root`**. Если написано `root` — дефект.

Если скрипт сообщил о переносе `@includedir`, убедитесь, что бэкап создан:

```bash
ls -l /etc/sudoers.butler.bak
sudo visudo -c
```

**Ожидается:** `/etc/sudoers: parsed OK`.

Ключевая проверка — беспарольный вызов `ufw` **в новой сессии**
(членство в группе `systemd-journal` применяется только после перезахода):

```bash
exit
ssh user@server
sudo -n ufw status
```

**Ожидается:** статус UFW выводится без запроса пароля.
Если появилось `sudo: a password is required` — дефект, см. Диагностику.

```bash
sudo systemctl restart butler
```

## 5. Веб-интерфейс

Откройте `http://<ip-сервера>:5050`.

| № | Действие | Ожидаемый результат |
|---|---|---|
| 5.1 | Открыть любую страницу без входа | Редирект на `/login` |
| 5.2 | Ввести неверный пароль | Сообщение «Неверный логин или пароль» |
| 5.3 | Ввести данные из `butler.env` | Вход выполнен, открылась главная |
| 5.4 | Пройти по всем разделам: Сервисы, Белый список, Чёрный список, Firewall, Попытки, Журнал | Все страницы открываются, без 500 и без `Bad Request` |
| 5.5 | Нажать «Выйти» | Возврат на `/login` |

**Отдельно:** ни одно действие не должно давать
`Bad Request — CSRF token missing or invalid`. Это была реальная регрессия,
проверьте внимательно каждую кнопку.

## 7. Применение правил (самое важное)

**Перед этим шагом убедитесь, что ваш IP есть в белом списке для SSH
(шаг 6.5), и что снапшот ВМ сделан.**

```bash
sudo ufw status numbered          # зафиксировать состояние ДО
```

| № | Действие | Ожидаемый результат |
|---|---|---|
| 7.1 | Firewall → «Сохранить в файл» | Правила выгружены, путь показан в сообщении |
| 7.2 | Firewall → «Применить правила» | Успех, SSH-сессия **не оборвалась** |
| 7.3 | `sudo ufw status numbered` в терминале | Правила из панели присутствуют |
| 7.4 | Открыть панель в браузере после применения | Панель доступна, порт 5050 не заблокирован |
| 7.5 | Нажать «Применить правила» второй раз, ничего не меняя | Дубликаты правил не появились (идемпотентность) |
| 7.6 | Добавить IP в белый список и применить снова | Добавилось только новое правило, прежние не пересозданы |
| 7.7 | Переключить режим «белый список» ↔ «чёрный список» и применить | Набор правил сменился согласно режиму, SSH остался открыт |
| 7.8 | Проверить чужие правила, добавленные вручную до теста | Не удалены и не изменены |
| 7.9 | Firewall → «Сбросить правила» | Butler-правила убраны, SSH и порт панели по-прежнему открыты |

Если UFW был выключен, Butler включит его при первом применении правил, предварительно
разрешив SSH и порт панели.

## 8. Попытки подключений и журнал

| № | Действие | Ожидаемый результат |
|---|---|---|
| 8.1 | С другой машины постучаться на закрытый порт: `nc -vz <ip> 9999` | Соединение отклонено |
| 8.2 | Запустить сбор логов, не ждав таймер: `sudo systemctl start butler-log-import.service` | Команда завершилась без ошибок |

| 8.6 | Открыть «Журнал» | Все действия из шагов 6–7 записаны с датой и пользователем |

```bash
sudo journalctl -u butler-log-import -n 30 --no-pager
```

**Ожидается:** периодические запуски без трассировок исключений.

## 9. Автотесты

На сборочной машине, из корня репозитория:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt pytest
.venv/bin/python -m pytest -q
```

**Ожидается:** `67 passed`.

Запускать на Python 3.11–3.13. На Python 3.14 тесты падают с
`AttributeError: module 'ast' has no attribute 'Str'` — это несовместимость
Werkzeug 2.2.3 с новым Python, а не дефект Butler.

## 10. Перезагрузка и снятие

```bash
sudo reboot
```

После перезагрузки:

```bash
systemctl is-active butler                     # active
systemctl is-active butler-log-import.timer    # active
sudo ufw status                                # правила сохранились
```

Снятие:

```bash
cd ~/butler
./install.sh --uninstall     # служба снята, БД и конфиг на месте
./sudoers.sh --remove        # правило sudoers удалено
```

**Ожидается:** обе команды завершаются успешно, `sudo visudo -c` по-прежнему
даёт `parsed OK`.

## Диагностика

**`ERROR: Could not find a version that satisfies the requirement MarkupSafe`
при `install.sh`**
ABI wheels не совпадает с Python сервера. Проверьте:
`ls .butler/wheels/ | grep -i markupsafe` и `python3 -V`. Пересоберите архив
с нужными `--python-version` и `--abi`.

**`sudo: a password is required` в веб-интерфейсе**
Правило sudoers перекрыто. Смотрите порядок:

```bash
sudo -l -U <пользователь>
grep -n '@includedir' /etc/sudoers
```

В sudoers побеждает последнее совпавшее правило. Если ниже `@includedir` есть
`%astra-admin ALL=(ALL:ALL) ALL`, оно перекрывает `NOPASSWD` — перезапустите
`./sudoers.sh`, он переносит `@includedir` в конец файла.

**`Bad Request — CSRF token missing or invalid`**
В шаблоне формы нет скрытого поля `csrf_token`. Зафиксируйте, на какой
странице и какой кнопке это произошло.

**Служба не поднимается**

```bash
sudo journalctl -u butler -n 50 --no-pager
```

**Потерян доступ по SSH после применения правил**
Заходите через консоль гипервизора и снимайте правила:

```bash
sudo ufw disable
```

Затем восстановите снапшот и зафиксируйте, какие правила были применены.
